# 本地音色工作区验收记录

基于 `97bd017` 在 `codex/indextts-producer-validation-web` 分支实现。环境沿用 RTX 2060 / Python 3.11.13 / Torch 2.8.0+cu128，具体版本见 [environment.json](environment.json)。本轮未处理交接目录，未删除原有交接包，未修改父仓库文件。

## 自动验证

[pytest.txt](pytest.txt)：122 项通过，包含原制包、reader 和情感回归，以及新增的持久化音色库、两档版本、非法参数、参考来源不匹配、损坏包、重复导入、删除确认、失败保留、最近结果替换、请求快照、排队取消、缺少 CUDA、模型精度不匹配、子进程退出/取消/恢复、Gradio 三页签构建测试。依赖警告不影响通过。

[real-regression.json](real-regression.json)：实际启动两个 reader 子进程，分别加载已存在的 FP32/BF16 裁剪模型；使用同一参考生成的相应精度包、文本“今天阳光很好。”和 seed=17。

- 两档均验证旧 JSONL 请求（不传 `generationSettings`）与显式默认配置的 WAV SHA-256 完全相等。
- 两档均验证将声学步数从 25 改为 10、CFG 从 0.7 改为 0.5 后，报告的生效参数及音频哈希发生变化。
- 报告保存每次请求的生效参数、时间、RTF、输出哈希以及 reader health、模型精度和包指纹。不同精度本身未要求互相数值相等。

复现命令和路径配置见 [使用说明](../../voice-workbench.md)。使用者需要自行准备两档模型与对应音色；测试脚本不导出或修改模型。

## 浏览器验证

通过本机 `http://127.0.0.1:7861` 实际完成：

- 上传 `examples/voice_01.wav`，新建 `workbench-test-01`，FP32 制包约 43.95 秒，保存原始参考及包；在音色库填写备注。
- 选择已有 FP32 裁剪模型，生成、播放、下载 WAV。首次模型加载约 46.47 秒，短句合成约 5.13 秒，音频约 1.83 秒，RTF 2.796，见 [browser-fp32.json](browser-fp32.json)。
- 从试听页跳转补生成 BF16，沿用库中固定参考；选择已有 BF16 模型，再生成、播放和下载。加载约 39.03 秒，短句合成约 6.37 秒，音频约 1.92 秒，RTF 3.320，见 [browser-bf16.json](browser-bf16.json)。
- 在页面将声学步数设为 10、CFG 设为 0.5；复用模型合成约 3.40 秒，RTF 1.771，见 [browser-bf16-custom.json](browser-bf16-custom.json)。这只验证参数可用，不评价降低步数后的音质。
- 长文本运行中取消后，旧试听结果仍在。最终页面另外验证了模型加载期间取消，显示“试听已取消，上一次成功结果仍保留”，对应 reader 子进程退出，没有遗留运行中的 reader。
- 取消后再次生成成功，模型重新加载约 29.91 秒，BF16 合成约 4.44 秒，输出约 1.92 秒，见 [browser-recovery.json](browser-recovery.json)。
- 重启服务、刷新页面后，仍可选择同一个音色，读取备注、两档版本、分别保存的模型目录和最近试听。
- 文件检查显示每种精度只保留一个 WAV 和一个报告，没有累积历史试听，见 [latest-only.json](latest-only.json)。

验证期间修复了切换页签后版本状态未刷新、Windows 子进程异常退出后的管道关闭错误，以及正常取消被显示为错误覆盖层的问题。

浏览器日志曾在页面刷新/音频组件切换时记录 Gradio 5.45 波形组件的 `ResizeObserver` 空元素错误；重启后的音频波形、播放、下载及继续合成功能均可操作。本轮没有修改 Gradio 的打包前端依赖。

以上耗时均为本机单次功能验证，不是稳定性能基准；图形/模型加载及系统状态会影响结果。显存报告来自 PyTorch 当前分配/保留和进程生命周期峰值，不等于专用显存或系统总内存。本轮已验证可播放和下载，不代表已经完成主观克隆音色质量评价。
